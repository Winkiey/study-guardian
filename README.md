# 学习守护 · Study Guardian

**课程表 · 课件在线预览 · 作业 DDL 手机提醒**

一个自己部署、自己掌控的学习助手：**课表、课件、作业 DDL 集中在一处，数据存在你自己的机器上。**
为「不想再翻聊天记录找课件、不想再忘记交作业」而写。

可以只自己用，也可以让同学各自注册账号 —— **数据互相看不见**（见[账号与多用户](#账号与多用户)）。

[![Node.js](https://img.shields.io/badge/Node.js-%E2%89%A522.5-339933?logo=nodejs&logoColor=white)](https://nodejs.org)
[![依赖](https://img.shields.io/badge/dependencies-0-brightgreen)](package.json)
[![许可](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

**零第三方依赖**——不需要 `npm install`，不需要构建工具，没有 `node_modules`。
只要能跑 Node.js，三条命令就能用：

```bash
git clone https://github.com/Winkiey/study-guardian.git
cd study-guardian
node server.js
```

然后打开 <http://127.0.0.1:3081>，按引导创建账号即可。

> 想让手机也能打开、并且不在家时也能看？**不用买服务器**，
> 见 [部署：让提醒真正可靠](#部署让提醒真正可靠)。

## 它能做什么

| 你可能遇到的问题 | 这个平台怎么解决 |
| --- | --- |
| 记不清下节课在哪、几点上 | 周课表视图，按「第几周」自动过滤单双周、调课 |
| 不知道这门课总评怎么算的 | 录入成绩构成（平时 30% + 期末 70%），随时看还差多少分 |
| 老师发的 PPT 散落在微信、QQ、学习通里 | 全部传进资料库，**点开直接在线看**，不用下载再打开 |
| 快考试了想找「第 5 周讲的那个知识点」 | 全站搜索连 PPT 正文一起搜 |
| 忘记交作业 | 设置 DDL + 提前多久提醒，到点推送到手机（Bark / 邮件 / 企业微信…） |
| 想在手机日历里看课表 | 导出 `.ics` 导入 iPhone 日历，或加订阅链接自动同步 |
| 想和同学合用一台服务器 | 各自注册账号，**数据完全隔离**；不开放注册就谁也别想进来 |

## 三分钟上手

### 前置要求

只需要 **Node.js v22.5.0 或更高**（[下载地址](https://nodejs.org)，选 LTS 版本）。

> 为什么要 22.5+：本平台用 Node 内置的 `node:sqlite` 存数据，
> 这样就不需要 better-sqlite3 那种要编译的原生模块，也就不会有「装不上」的麻烦。

### 启动

```bash
node server.js
```

**Windows 用户**：也可以直接双击项目里的 **`启动学习守护.cmd`**，
效果一样，省得敲命令。关掉那个窗口就是停止服务。

> 双击后它会先问一句「Start it?」，**要手动输入 `Y` 才会真的启动**。
> 这不是多余的礼节 —— 误触一个 `.cmd` 很容易，而**跑第二份副本是有害的**：
> 每份副本有各自的 `data/app.db` 和各自的提醒调度器，
> 同一个作业 DDL 会往你手机**推两遍**，而且两份数据会各自走远
> （你正在看的这份未必是发通知的那份）。已经在服务器上跑着的话，
> 这个窗口完全不需要。

看到这样的输出就成功了：

```
  访问地址   http://127.0.0.1:3081
  数据目录   .../学习守护平台/data
  Office 转换 Microsoft Office（COM 自动化）
  提醒调度   每 60 秒检查一次
```

**首次打开**会引导你创建账号（用户名 + 密码）。账号只存在你自己电脑的 `data/app.db` 里。
密码用 scrypt 加盐哈希存储，不会上传到任何地方。

### 装不上？先跑自检

```bash
npm run doctor
```

它会逐项检查 Node 版本、目录权限、端口、Office 预览能力、通知渠道配置，
并直接告诉你「哪里有问题、怎么办」。

> **已经跑起来了、但某个功能不对劲？** 另外两个自检脚本更对症：
>
> ```bash
> node scripts/diagnose-preview.mjs   # 课件打不开 / 只有文字没有排版 / 中文变方框
> node scripts/e2e.js                 # 改过代码之后，确认没把别的地方弄坏
> ```
>
> 前者会把磁盘、内存、有没有残留进程、转换器、中文字体、最近每份课件的状态
> 一次性打出来，省得靠猜。它只读数据，不改任何东西。

## 1. 课程管理

### 课程信息

每门课可以记录：课程名、课程号、任课教师、教师联系方式、学分、学时、
课程性质（必修/选修）、考核方式（考试/考查）、常用教室、颜色标记、备注。

### 上课时间

**每一门课的时间都能自己改**：课程详情页 →「上课时间」卡片 →「编辑上课时间」。
可以增删时间段，也可以直接改星期、开始/结束时间、周次、教室。

支持真实的课表复杂度：

| 写法 | 含义 |
| --- | --- |
| `1-16` | 第 1 到 16 周 |
| `1-16单` | 第 1 到 16 周的奇数周 |
| `1-16双` | 偶数周 |
| `1-8,10-16` | 多段 |
| `3` | 只有第 3 周 |

一门课可以有多个上课时间（比如高等数学周一 1-2 节 + 周三 3-4 节）。
调课、停课也能单独记录，课表会跟着变。

### 作息时间表（「第几节」是几点）

每个学校的上课时间都不一样，所以这张表**由你自己维护**：
**设置 → 作息时间**。

填法是**一节一行**：

| 节次 | 开始 | 结束 |
| --- | --- | --- |
| 第 1 节 | 08:00 | 08:45 |
| 第 2 节 | 08:50 | 09:35 |
| 第 3 节 | 09:55 | 10:40 |
| … | | |

它影响两件事：

1. **导入课表时**，教务系统写「第 3-4 节」「第 5-7 节」的会按这里换算成具体时间
2. **课程表页**的时间轴按这里的节次分行，跨节次的课会占对应行数的高度

> **为什么是「一节一行」而不是「第1-2节一行」？**
> 因为真实课表里既有「第 5-6 节」也有「第 5-7 节」。
> 如果按区段存（第5-6节一行、第7-8节一行），「第 5-7 节」的结束时间就会错误地
> 取到第 7-8 节那一行的末尾。按单节课存，任意跨度都能算对：
> 第 5-7 节 = 第5节的开始 → 第7节的结束。

默认值是一份「45 分钟一节课、课间 5 分钟」的常见编排，和你们学校不一致就在这里改。
设置页有「按上一节自动推算下一节」，填的时候不用一节一节手敲。

> 已经导入的课程不会自动跟着变——去课程详情页点「编辑上课时间」可以直接改单门课的时间。

### 成绩构成

按教务系统的比例录入，例如：

| 项目 | 占比 | 得分 |
| --- | --- | --- |
| 平时成绩 | 30% | 88 |
| 期中考试 | 20% | 76 |
| 期末考试 | 50% | 未出分 |

平台会算出：

- **已得分数** 41.6（88×0.3 + 76×0.2）
- **已出分部分得分率** 83.2%（41.6 ÷ 50）
- **最终总评区间** 41.6 ~ 91.6（剩余部分从 0 分到满分的范围）

## 2. 课件在线预览

把老师发的 PPT、PDF、Word、Excel、图片、音视频传进资料库，**点开就能在网页里看**，
不用下载再用本地软件打开。

### 预览是怎么做的

| 文件类型 | 预览方式 |
| --- | --- |
| PDF | 浏览器自带 PDF 阅读器（支持缩放、翻页、全文检索、打印） |
| PPT / PPTX / Word / Excel | 先转成 PDF，再用上面的方式显示 —— **效果和原件一致** |
| 图片 / 视频 / 音频 | 原生渲染，视频支持拖动进度条 |
| TXT / MD / 代码 | 直接显示（自动识别 UTF-8 与 GBK 编码） |
| 转不了 PDF 的 Office 文件 | 自动降级成「网页版预览」：抽出文字按页/按段落渲染 |

> **降级是怎么回事**：如果不满足下面的转换条件，PPT 会退化成只显示文字的网页版
> （排版和图片不显示），并在页面上明确告诉你原因。课件数据不会丢，也随时能下载原件。

### 让 PPT 预览效果和原件一致

平台会自动探测本机有没有装下面任意一个（**装一个就够**）：

1. **LibreOffice**（免费开源，跨平台，推荐）—— [libreoffice.org](https://www.libreoffice.org/)
2. **Microsoft Office**（Windows，用 COM 自动化调用）
3. **WPS Office**（Windows）

装好后重启服务即可，设置页会显示探测结果。
不想装也能用，只是 PPT/Word 走网页版文字预览。

### 其它实用功能

- **全屏观看**：预览页右上角有「全屏」，点一下课件铺满整个屏幕
  （见下文）
- **全文检索**：搜索会连 PPT 正文、Word 段落一起搜，找「第 5 周讲的那个概念」很好用
- **按课程 / 分类筛选**：课件、讲义、作业、试卷、资料、教材、其他
  （顶部标签上带数量，一眼看出哪门课的资料还没传）
- **批量上传**：直接把一堆文件拖进上传框
- **标签与周次**：`第 5 周`、`重点,期末复习`

> 上传和编辑时都能改分类；资料库顶部的标签按分类筛选。
> 分类是固定的这几项（不让你随手造新词），这样筛选和统计才不会散成几十种写法。

#### 全屏观看

课件预览页右上角有个「全屏」按钮，点一下预览区就铺满整个屏幕 ——
网站自己的导航、侧边栏都收起来，能看的面积最大化。右下角有「退出全屏」，按 `Esc` 也行。

对**所有**预览方式都有效：PDF、幻灯片图片、网页版预览、纯文本。

> 手机上也能用。桌面浏览器还会顺便请求一次系统级全屏（连地址栏一起收掉），
> 但**不依赖它** —— iPhone 的 Safari 不允许网页对普通区域做系统级全屏，
> 那里就是单纯的「铺满视口」，照样比以前能看的面积大得多。

#### 手机上打开 PDF 课件会看到一条提示

这不是 bug，是苹果的限制：

**iPhone / iPad 的 Safari 在网页里内嵌 PDF 时，只渲染第一页，而且不给滚动。**
所以你在手机上打开一份 PDF 课件，看到的会是一份「只有一页的课件」，
很容易以为文件传坏了或者上传没成功。

平台会在**认出来是 iPhone / iPad** 时，在 PDF 预览区上方显示一条提示，
里面有个「在新标签页打开」的按钮 —— 点它会交给 iOS 自带的 PDF 阅读器，
翻页、缩放、搜索都正常。

> 只在 iOS 上显示：桌面浏览器点开 PDF 是好的，不需要这条提示。
> 判断放在前端而不是服务端，是因为 iPadOS 13 起 Safari 的 User-Agent
> 和 Mac 一模一样，服务端光看 UA 分不出来。
>
> **幻灯片图片模式不受影响** —— 那种模式每页都是一张图，手机上完全正常。
> 服务器上的 PPT 大多转成了 PDF，所以这条提示基本都会遇到。

## 3. 作业 DDL 与手机提醒

### 建作业

填标题、所属课程、截止时间，勾选「提前多久提醒」：

```
☑ 提前 1 周   ☑ 提前 1 天   ☑ 提前 2 小时   ☐ 提前 30 分钟
```

保存后平台会**自动生成对应的待发提醒**。改了 DDL 或把作业标记为已完成，
提醒会跟着重建或取消 —— 不需要手动维护。

### 配置推送渠道

进「设置 → 手机提醒 → 添加渠道」。内置 11 种：

| 渠道 | 适合谁 | 说明 |
| --- | --- | --- |
| **Bark** | **iPhone 用户（最推荐）** | App Store 装个 Bark，把首页那串 Key 填进来，**不用注册账号** |
| 邮件 | 所有人 | 发到你自己邮箱，手机邮件 App 会弹通知。需填 SMTP 授权码 |
| 企业微信机器人 | 国内通用 | 群里加个机器人，复制 Webhook 地址 |
| 钉钉机器人 | 国内通用 | 支持加签校验 |
| 飞书机器人 | 国内通用 | 支持签名校验 |
| ntfy | 想要开源方案 | 可用官方服务器，也可完全自建 |
| PushPlus / Server 酱 | 想用微信收 | 关注公众号即可 |
| Telegram | 海外 | 支持自建反代地址 |
| Gotify | 想完全自托管 | 数据不出自己的服务器 |
| 自定义 Webhook | 想接自己的系统 | POST 一段 JSON 到任意地址 |

**添加渠道时会自动发一条测试消息**，填错了立刻就报错，不用等到作业到期才发现。

### iPhone 用户五分钟配好 Bark

1. App Store 搜索 **Bark** 安装（免费开源，不用注册账号）
2. 第一次打开时 iOS 会问通知权限，**必须点「允许」**
3. 打开 App，首页会显示一串字符，形如 `AbCdEf123456` —— 这就是推送 Key
4. 本平台「设置 → 手机提醒 → 添加渠道 → Bark」，把 Key 粘进去

   > 也可以直接复制 Bark 首页显示的那一整段网址
   > （`https://api.day.app/AbCdEf123456`）粘进来，平台会自动拆成
   > 「服务器地址 + Key」，两种都行。

5. 提示音在「设置 → 提示音」里可以先试听，挑一个喜欢的（默认 `bell`）
6. 通知级别保持默认的**「时效性通知」**，它能穿透 iPhone 的「专注模式」
7. 点「发送测试」——收到了就说明配好了，再保存

**没收到测试消息？** 按这个顺序排查：

1. 先看 Bark App 里有没有这条历史消息。
   有 → 推送发出去了，是手机的通知被挡住了，往下看；
   没有 → Key 或服务器地址不对，回 Bark 首页重新复制一次 Key。
2. iPhone「设置 → 通知 → Bark」，确认「允许通知」开着。
3. 开着专注模式 / 勿扰模式？去「设置 → 通知 → Bark → 时效性通知」把开关打开
   （光在平台里选「时效性通知」不够，iOS 那边也要允许）。
4. 手机静音时通知不会响，改用「重要警告」级别需要在 iOS 里单独授权。

添加渠道时平台会**自动帮你把 Key 里的空格、换行、多余网址清理干净**，
并把 Bark 的英文报错（比如 `device token is not exists`）翻译成中文的排查建议。

### 每日简报（可选）

设置里可以打开「每日简报」，每天早上定时把「今天有哪几节课 + 未来一周的待办作业」
推送到你手机。开机第一件事就看一眼，不容易漏事。

开关、发送时间、用哪个渠道都是**每个账号各设一份**，互不影响。

简报发不出去时的行为是有讲究的：

| 情况 | 平台会怎么做 |
| --- | --- |
| 还没配任何启用的渠道 | 安静跳过，**不记失败**。你配好渠道后最多 60 秒就会发出来 |
| 渠道配了但发失败（比如 Key 填错） | 每隔 30 分钟重试，**一天最多试 3 次**，之后停下来等第二天 |
| 发出去了 | 记下「今天已发」，当天不再重复发 |

> 为什么要限制次数：调度器默认每 60 秒跑一次。如果失败就无脑重试，
> 一天会在发送日志里堆 1440 条一模一样的失败记录，把「设置 → 提醒调度」
> 里那 30 行的日志视图彻底糊住，反而看不到真正的问题。
> 一天的 3 次失败足够让日志告诉你「渠道坏了」，又不会淹没别的东西。

### ⚠️ 关于提醒可靠性，必须说清楚

**提醒是由这个平台的服务进程发出去的。电脑关机 / 服务停止时，提醒不会发出。**

- 只在自己电脑上跑 → 电脑开着的时候提醒是准时的，关机就收不到
- 想要 7×24 可靠提醒 → 把服务放到一台常开的机器上（[见下文](#部署让提醒真正可靠)）

平台在「设置 → 提醒调度」里如实显示调度器的运行状态和每一次发送记录，
方便你确认它到底有没有在工作。

## 把你的课表导进来

三种方式，按你的情况选。

### 方式一：导入 `.ics` 文件（最省事）

如果教务系统或手机日历能导出 `.ics`，直接上传。平台会自动识别：

- 课程名（会去掉「【必修】」这类修饰词）
- 教师（从描述里抽「任课教师：张三」）
- 学分（抽「学分：4」）
- 上课时间与**周次**（连「单周/双周」都能还原）
- 教室

上传后先给你一份**预览表格**，核对无误再点确认导入。同名课程可以选择跳过、合并或新建。

### 方式二：导入 CSV / Excel（最通用）

从教务系统把课表复制到 Excel，整理成这个格式，导出 CSV 上传：

```csv
课程名称,课程号,教师,学分,学时,课程性质,考核方式,星期,上课时间,周次,上课地点
高等数学(上),MATH101,张三,5,80,必修,考试,星期一,08:00-09:40,1-16,之远楼301
高等数学(上),MATH101,张三,5,80,必修,考试,星期三,10:00-11:40,1-16,之远楼301
微观经济学,ECON201,李四,3,48,必修,考试,星期二,13:30-15:10,1-16单,博学楼205
```

「导入课程表」页面可以**下载带示例的 CSV 模板**。
也可以直接把表格内容**粘贴**到输入框里，不用存文件。

表头别名做了容错：「课程名称 / 课程名 / 科目 / 教学班名称」都认，
「教师 / 任课教师 / 授课教师 / 老师」都认。GBK 编码的文件也能正确读。
时间列写「第 3-4 节」或「10:00-11:40」都行，会按国内常见作息表换算。

### 方式三：手动添加

课少的时候最快。添加课程 → 设置上课时间 → 设置成绩构成。

### 关于东北财经大学教务系统

教务处系统是否支持导出 `.ics`，不同学校、甚至不同年份都不一样。
建议按这个顺序试：

1. **教务系统课表页面找「导出 / 下载 / 打印」按钮** —— 有些能直接导 ICS 或 Excel
2. **学校官方课表小程序 / App** —— 有些支持「导出到手机日历」，导出后在手机日历里
   再导出一次就是 `.ics`
3. **用 Excel 手工整理** —— 从教务系统把课表复制到 Excel，按模板排好列再导入（最稳的兜底）
4. **第三方课表 App** —— 有些 App 支持导入教务课表后导出 `.ics`

> **想做「一键同步」？** 代码里已经预留了「教务系统适配器」的位置。
> 如果你愿意帮忙摸清东财教务系统的接口（正方 / 强智 / URP 等），
> 就能做成登录后自动拉课表。欢迎提 Issue 或 PR。

### 导出到手机日历

「设置 → 课表导入导出」提供两种方式，**用途不同**：

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| **下载 `.ics` 导入** | 事件自带闹钟，到点手机会响 | 课表改了要重新导入 |
| **订阅链接** | 自动更新，课表一改手机就变 | **iOS 会忽略订阅日历的闹钟**，只能用来看 |

所以：**看课表用订阅，要提醒用 Bark。**

### 订阅链接是钥匙，所以它能换掉

订阅链接和别的东西不一样：**它不需要登录就能用**。手机自带的日历不会带登录信息，
所以只能把「通行证」直接放进网址里 —— 谁拿到这条链接，谁就能看到你的课表和作业
（只读，改不了任何东西），而且有效期一年。

所以它要按「钥匙」来对待：别截图发出去、别粘到群里。真要是怀疑被谁抄走了
（截图过、投屏过、发给过同学、在公共 WiFi 上用过），去
**设置 → 课表导入导出 → 重新生成订阅链接**：

- 以前发出去的所有链接**立刻失效**（手机日历里需要重新添加一次订阅）
- 只影响你自己，**不会**影响同学
- 也不会把你自己的登录状态弄掉

顺带有两个相关的按钮/行为：

- **设置 → 账号 → 退出其他所有设备**：把所有别处的登录踢掉，当前这台不受影响。
- **改密码**会顺手做两件事：踢掉其他设备、**并把已经发出去的订阅链接一起作废**
  （钥匙多半就是从同一个地方丢的）。

这些之所以能做到，是因为令牌里带了一个**计数**（`users.session_version` /
`calendar_version`），作废就是把这个计数 +1。在此之前只能靠换 `SESSION_SECRET`——
而那是全站的总钥匙，代价是**所有人**重新登录一遍。

> ⚠️ 升级到带计数的版本**不会**把任何人踢下线，也**不会**让已经订阅好的手机日历失效。
> 旧格式的令牌按计数 0 处理，只有你真的点过「重新生成」或「改密码」之后才会失效。

## 部署：让提醒真正可靠

> 📘 **想要一个「随时输网址就能打开」的网站，不依赖自己电脑开着？**
> 看 **[部署到云服务器（免备案）](DEPLOY.md)** —— 从买服务器到上线的逐步清单，
> 含端口放行、时区设置和数据迁移，照着做约 20 分钟。

### 需要买服务器吗？大多数情况下不需要

只要有一台**能长期开着的电脑**（日常用的笔记本、家里的旧电脑、NAS、树莓派都算），就足够跑这个平台。
真正要解决的不是「服务器」，而是**怎么让手机在外面也能打开它**——这两件事是分开的。

| 方式 | 在哪能打开 | 花钱吗 | 适合谁 |
| --- | --- | --- | --- |
| 只在本机 | 只有这台电脑 | 不用 | 先跑起来看看 |
| 同一个 Wi-Fi | 在家 | 不用 | 手机在家看课表 |
| **Tailscale** | 任何地方 | **免费** | **自用最推荐** |
| Cloudflare Tunnel | 任何地方、任何浏览器 | 域名约 ¥60/年 | 想分享给别人 |
| 云服务器 | 任何地方 | ¥10–30/月 | 电脑没法常开 |

### 先澄清一件事：提醒不需要「手机能连上你的电脑」

Bark / 邮件这类推送是**电脑主动发出去的**：到点了，你电脑上的服务把消息发给 Bark 的服务器，
Bark 再推到你手机。手机不需要能访问你的电脑，也不需要你在外面能打开这个网页。

所以如果你的核心诉求只是「**别忘了交作业**」，那**电脑常开就够了，什么都不用额外配**。
「在外面也能打开网页看课表」是锦上添花，按下面的方式选一个即可。

### 方式一：只在自己电脑上（默认，最安全）

```bash
node server.js
```

只监听 `127.0.0.1:3081`，只有这台电脑能访问。

### 方式二：同一个 Wi-Fi（手机在家能看）

把 `.env` 里的 `HOST` 改成 `0.0.0.0`，重启后手机连同一个 Wi-Fi 就能访问
`http://电脑的局域网IP:3081`（启动时终端会把地址打出来）。

> ⚠️ 改成 `0.0.0.0` 后，**同一 Wi-Fi 下的其他人也能打开**。
> 账号密码是唯一防线，别用弱密码。

### 方式三：Tailscale（自用最推荐）

[Tailscale](https://tailscale.com) 是一个免费的内网穿透工具，正好解决自用的痛点：

- **免费**，个人版够用，不用买域名也不用买服务器
- **不需要公网 IP**（国内家庭宽带大多是运营商 NAT，端口转发基本用不了，这条很关键）
- 电脑和手机装好登录同一个账号后，会得到一个固定网址，形如
  `https://你的电脑名.你的网络名.ts.net`
- **只有你自己的设备能访问**——不暴露在公网上，别人扫不到，比公网映射安全得多
- 自带 HTTPS 证书，手机上「添加到主屏幕」和剪贴板功能都能正常用

配置就三步：

1. 电脑和 iPhone 各装一个 Tailscale，登录同一个账号
2. 在 Tailscale 后台开启 MagicDNS 和 HTTPS
3. 用 `tailscale serve 3081` 把本地端口暴露给你的内网

之后手机在任何网络下（4G/5G/别人的 Wi-Fi）都能打开那个网址。

### 方式四：Cloudflare Tunnel —— 想要一个公开网址

如果希望**任何浏览器**都能打开（比如分享给同学），用 Cloudflare Tunnel 加一个便宜域名：

```bash
cloudflared tunnel --url http://127.0.0.1:3081
```

它和 Tailscale 一样不需要公网 IP。区别是**它真的把服务放到了公网**，
所以务必按下面的 HTTPS 一节加一层保护，并且用强密码。

### 方式五：什么时候才真的需要云服务器

只有一种情况：**你的电脑没法一直开着**（比如笔记本要带出门、宿舍晚上断电）。

那时候再考虑阿里云 / 腾讯云的学生机（一个月十块左右），按下面的步骤部署。

### 🔒 想让别人也能访问，就一定要加 HTTPS

这个平台是为「个人自用 / 局域网」设计的，**没有做抗攻击加固**，不要裸着暴露到公网。
用 Caddy 最省事，它会自动申请并续期证书：

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile` 改成（域名换成你自己的）：

```caddyfile
学习.example.com {
    reverse_proxy 127.0.0.1:3081
}
```

```bash
sudo systemctl reload caddy
```

> 用 Docker 时，把 `docker-compose.yml` 的端口改成只绑本机 `127.0.0.1:3081:3081`，
> 免得有人绕过 HTTPS 直接从 3081 访问。

HTTPS 不只是「更安全」，还直接影响两个功能：

- **剪贴板复制在纯 HTTP 下不可用** —— 浏览器只在安全上下文里提供 `navigator.clipboard`。
  程序会自动降级成「帮你选中文本，你自己按复制」，但体验差一截。
- **网页应用清单（manifest）在纯 HTTP 下不生效** —— 图标、名称、全屏打开这些会退回默认值。
  iOS 靠 `apple-*` 那组标签在 HTTP 下**仍然能「添加到主屏幕」**，只是效果不完整。

所以：只是想打开看看，HTTP 够用；想装成手机上的 App 那样用，就上 HTTPS。

> 🔑 账号密码是这个平台唯一的防线。它**没有**短信验证、没有登录失败锁定，
> 别用弱密码，也别把它当成能抗攻击的公网服务。

### 已经做了什么（不需要你配）

有件事不用等 HTTPS —— 程序自己会发这几个响应头，**任何部署方式下都生效**：

| 响应头 | 作用 |
|---|---|
| `X-Content-Type-Options: nosniff` | 不让浏览器猜文件类型。本站会把上传的文件原样发回去，猜错了就可能把上传的 `.html` 当页面执行 |
| `X-Frame-Options: SAMEORIGIN` + CSP `frame-ancestors 'self'` | 不许**别的站**用 iframe 把你套起来（点按劫持的经典手法） |
| `Referrer-Policy: strict-origin-when-cross-origin` | 跳到外站时只带域名，不带完整地址 |
| `Permissions-Policy` | 明确关掉摄像头、麦克风、定位等用不到的能力 |
| `X-Robots-Tag: noindex, nofollow` | 私人数据，别被搜索引擎收录 |

两处**刻意**这么写的地方，改之前请先看 `server.js` 里的注释：

- **`frame-ancestors` 是 `'self'`，不是 `'none'`。** 这条头会加到所有响应上，
  包括 `/materials/:id/pdf` —— 而 PDF 预览页恰恰是**自己用同源 iframe 嵌自己的 PDF**。
  写成 `'none'` 会把那个 iframe 一起挡掉，**PDF 预览直接白屏**。
  `'self'` 一样挡得住第三方，只是放行自己。
- **CSP 里没有 `default-src` / `script-src` / `style-src`。** 页面里有内联主题脚本和
  大量 `style="--dot-color:…"` 内联样式（课程颜色就靠它）。写上这些指令会把内联样式
  全部拦掉 —— 表现是「课程颜色没了」，而且不会有任何报错，很难联想到是 CSP 干的。

另外，**访问日志里的凭据会打码**：日历订阅地址带着 `?token=…`，而手机日历会定时轮询它，
那个 token 是「拿到就能拉走全部课表和作业」的凭据。日志里只留下 `token=***`。

### Windows 上长期开着，注意这三点

1. **别注销 Windows 账号**，锁屏没关系。注销会连同服务一起关掉。
2. 重启电脑后需要重新登录一次，服务才会跟着起来（除非你在「启动」文件夹里放了快捷方式）。
3. PPT 预览在 Windows 上走的是 Office 自动化，需要一个已登录的桌面会话；
   如果发现预览经常失败，装一个 [LibreOffice](https://www.libreoffice.org) 即可绕开。

## 账号与多用户

打开网站，**登录和注册在同一个页面上**，两栏切换，自己选。

<img alt="登录页：登录 / 注册两个分栏" src="docs/login-tabs.svg" width="360">

> 上图画的是页面结构，不是截图——样式以实际运行为准。

### 数据是互相隔离的

每个人注册一个账号，各看各的：

| | 说明 |
| --- | --- |
| 课程、课表、作业、课件、提醒 | 每一条都记在**你自己的账号**下 |
| 别人能不能看到 | 看不到。接口按 `user_id` 过滤，直接按 id 猜别人的网址也只会得到 404 |
| 别人能不能删你的东西 | 不能。改、删都先验归属 |
| 每日简报 / 推送设置 | 每个人自己设，各发各的 |

实现上只有一条规则：**每个查询都必须带上 `user_id`**。
这条规则漏一次，界面上完全看不出来 —— 每个人看到的都「像是自己的东西」。
所以端到端自测里有一整节专门验证隔离（用两个真账号互相对撞）。

### 用户名不能重名

- 用户名在数据库层面就是唯一的，撞车时提示是「用户名已经被占用了」，不是一串 SQL 报错
- **不区分大小写**：`Winkie` 和 `winkie` 算同一个名字。
  这是有意的 —— 登录本身不区分大小写，如果库里同时存在这两个账号，
  输入的时候就没法判断该登进哪一个
- 首尾空格会被忽略，所以 `小王` 和 ` 小王 ` 是同一个

### 要不要开放注册：邀请码

| `.env` 里 | 效果 |
| --- | --- |
| `INVITE_CODE=一串你定的字` | 别人注册时要填对邀请码才能建号 |
| 留空（默认） | **关闭注册**。注册那一栏会说「暂未开放」，只有已登录的人能用 |

默认是**关着**的 —— 宁可默认关门。服务器是按流量计费的，注册口敞着
等于把账单和磁盘交给路过的扫描器。

无论哪种情况，**站点上的第一个账号永远不需要邀请码**（否则你自己都进不去）。

### 密码要求

**至少 8 位**，注册和改密码都是这个下限（网页上的提示、前端校验、命令行脚本
全从 `src/lib/auth.js` 的 `PASSWORD_MIN_LENGTH` 取，不会出现「页面说要 8 位、
服务端只查 6 位」这种错位）。

> 加长下限**不影响已有账号**：登录只校验哈希、不看长度，
> 所以老密码哪怕只有 6 位照样能登进来，只是下次改密码时才受新规则约束。

建议长一点（16 位以上更稳），最省事的做法是用一句你记得住的话。
这个站没有登录失败锁定，密码就是唯一的门。

改完 `.env` 重启服务即可生效：

```bash
pm2 restart study-guardian
```

### 忘了密码

没有自助找回（发邮件、发短信那套要额外依赖，和「零依赖」冲突）。
**找站点管理员重置**，数据一点不动：

```bash
node scripts/reset-password.mjs 新密码 用户名
```

### 注销账号

设置页最下面有「注销账号」。点下去会：

1. 要你输**密码**（证明是本人）
2. 要你把**用户名原样敲一遍**（证明不是手滑）

两道都过了才真的执行，然后：

- 你的课表、作业、课件、提醒、推送记录**全部删除**
- 磁盘上你上传的课件、转出来的 PDF、幻灯片图片一并删掉
- 会话立刻失效，用户名被释放（别人可以注册同一个名字）

**没有回收站，不可撤销。** 唯一能补救的是你自己手上的备份。

### 不开注册，也想给某人开个号

```bash
node scripts/create-user.mjs 用户名 密码          # 直接建号
node scripts/create-user.mjs --list               # 看看现在有哪些账号
```

> `reset-password` 在站点有多个账号时**必须点名用户名**，不点名会直接拒绝并列出所有账号 ——
> 免得本来想帮同学重置，结果改错了人。

## 技术选型说明

这个项目做了一个不太常见的选择：**零第三方依赖**。

**没有 `npm install`，没有构建步骤，没有 `node_modules`。**

| 常规做法 | 本项目 | 为什么 |
| --- | --- | --- |
| Express / Fastify | Node 内置 `node:http` | 少一个依赖，少一个升级坑 |
| better-sqlite3（需编译） | Node 内置 `node:sqlite` | 不需要 C++ 编译工具链，装不上的问题直接消失 |
| bcrypt | Node 内置 `node:crypto` 的 scrypt | 免编译，安全性等价 |
| jsonwebtoken | HMAC-SHA256 签名 Cookie | 少一个依赖 |
| multer / busboy | 手写 multipart 解析器 | 只支持需要的那部分，可控 |
| nodemailer | 手写 SMTP 客户端 | 支持 STARTTLS / 隐式 TLS / 中文主题编码 |
| ical.js | 手写 RFC 5545 解析器 | 按需实现，含折行、RRULE、时区 |
| React / Next.js | 服务端渲染 + 原生 JS 渐进增强 | **禁用 JS 也能看课表**，首屏快，无构建 |

**带来的好处**：别人 `git clone` 之后一条命令就能跑起来。
对非计算机专业的同学来说，"要装 Node、要 npm install、还编译失败" 是很高的门槛。

**代价**：手写的东西测试必须做扎实。所以项目里有 **783 个单元测试**和
**约 727 项端到端断言**（数字会随着功能变，以跑出来的为准 ——
端到端里有几条要「看当前时间」才决定跑不跑，所以会在 725/727 之间浮动）：

```bash
npm test               # 单元测试：ICS 解析/生成、ZIP/ZIP64、Office 提取、SMTP、注销与多用户、设计令牌对比度
npm run test:e2e       # 端到端：在临时目录起真实服务，把全部主流程走一遍
npm run test:all       # 两个都跑（提交前建议跑这个）
```

端到端自测里有一节专门**用两个真账号互相对撞**，验证数据隔离：
一个人读、改、删另一个人的课程/作业/资料，全部必须得到 404 —— 不只是「改不动」，
返回码本身也要是 404：500 表示「这行存在但不是你的」、404 表示「没有这行」，
光看状态码就能把别人的数据 id 一个个试出来，所以两种情况必须回得一模一样。

#### 新加的断言要反向验一遍

界面类的断言很容易写成**永远为真**，那种断言和不写是一样的。所以这个项目的做法是：

> 每加一条守卫，就把对应的 bug **真的注入进去**，确认那几条断言确实变红，再改回来。

举几个真发生过的例子：

- 一条检查「样式表里有 `z-index: 50`」的断言，被它**自己上面那行注释**里的
  `z-index: 50` 匹配到了 —— 规则删掉了它照样绿。修法：匹配前先去掉注释。
- 一条写着「退出按钮排在预览区前面」的断言，用的是 `indexOf(A) < indexOf(B)`。
  钩子改名后 `indexOf` 返回 `-1`，而「任何数 > -1」都成立，于是它又是绿的。
  修法：先要求两边都能找到，再比大小。
- 一条验证「改不动别人的资料」的断言，写成了
  `materials.createMaterialRow ? 建一行 : null`，而**这个函数根本不存在**，
  于是它每次都在 `if (!row) return` 那里提前返回 —— 从头到尾没跑过一次。
  修法：改走真实的上传入口建数据，建不出来就直接判失败。
- 一条检查「空状态标题是 h2 不是 h3」的断言，查的是测试账号的课程表页面 ——
  而那个账号有课，页面**根本不是空状态**，一条空状态标题都没有，断言在空转。
  修法：专门注册一个没有任何数据的新账号去看，并且**先要求「确实渲染出了空状态」**。

最后一条里那个「先要求前置条件成立」，是这类断言的通用解法：
**只要断言依赖某个东西存在，就先断言那个东西真的存在。**
不然「东西不在」和「东西对了」在结果上长得一模一样。

同一个道理也适用于**测试窗口开太小**（用固定长度去找按钮文字，会被前面的 SVG 图标撑爆）
和**只验了一种模式**（iOS 提示只验了文字版和 Office 版，
把提示误加进「幻灯片图片」那条分支时全绿 —— 而服务器上的 PPT 恰恰大多是那个模式）。

#### 颜色也有测试守着

界面里唯一一种**改错了不会报错**的东西就是颜色。把三级文字从 `#5d6577`
改成浅一点的灰，页面照样渲染、功能测试照样全绿，只是日期和教室那些小字
变得看不清了 —— 而且只在某些底色上才看不清，肉眼抽查很容易漏。

所以 `tests/design-tokens.test.js` 直接从 `app.css` 里**解析出真实的色值**再算
对比度（不是抄一份常量进测试，那样改了 CSS 忘了改测试就永远对不上了），钉住四件事：

1. 正文、说明、三级文字、主色、状态色，压在**任何一层**底色上都要 ≥4.5:1。
2. 状态色压在自己的浅色底上（而那层底又叠在最深的灰面板上）也要 ≥4.5:1 ——
   徽标就是这个结构。以前只对着白底算，结果 `success` 在灰面板上只有 3.45:1。
3. 白字压在实心色底上要 ≥4.5:1（按钮和徽标都这么用）。
4. 两份深色定义（跟随系统 / 手动切换）必须**逐字一致** —— 不一致的后果很隐蔽：
   从系统跟随切到手动深色，页面颜色会变一下，而两边单独看都正常。

另外还钉了两条"审美"上的硬规则：全站只有一个品牌色（不许再引入第二个色相去做渐变），
以及不许把"文字用的主色"和"按钮底用的主色"合成一个令牌 —— 深色模式下
前者要够亮、后者要够深，一个值做不到两件事（硬合的话白字只有 2.71:1）。

#### 深浅色在哪里切

两个地方，都是同一个逻辑：

- **桌面**：左侧栏最下面（「退出登录」下面那一行）。点一下就换。
- **手机 / 想明确选一种**：设置 → 外观，三个选项：跟随系统 / 浅色 / 深色。

手机上侧栏是隐藏的，所以「设置 → 外观」是手机用户**唯一**的入口 ——
底部导航六项里有「设置」，点得进去。

默认是**跟随系统**（手机：设置 → 显示与亮度）。选了浅色或深色就固定下来、
不随系统变；想回去选「跟随系统」。

两个容易踩的点，都在 `tests/theme-switch.test.js` 里钉着：

- 以前只有侧栏那一个「切换」按钮 —— 手机上点不到（侧栏 `display:none`），
  而且点过一次之后就**再也回不到「跟随系统」**（值被永久写进了 localStorage）。
- 选「跟随系统」是**删掉** `sg-theme` 这个键，不是存成字符串 `"system"`。
  页面顶部那段防闪白的内联脚本靠「值不是 dark/light」来判定跟随系统，
  存一个 `"system"` 进去两边就会各判各的。

这个选择只存在当前设备的浏览器里（localStorage），不同步到账号。

#### 表单报错会说清是哪个框

以前填错了只有两条路：浏览器自带的气泡（样式不可控、点到别处就没了），
或者右上角一个 toast。toast 的问题是**不说是哪个框** ——
一个表单七八个字段，用户得自己一个个猜。

现在错误挂在出错的那个字段正下方，同时给输入框打上 `aria-invalid`
和 `aria-describedby`（读屏读到那个框时会念出错误内容）。用户一开始改，
错误就消失，不用等再次提交。

服务端返回的错误也尽量挂到具体字段上。判断逻辑是一个**纯函数**
（`pickErrorField`）：关键词命中**恰好一个**、而且那个字段确实在这个表单里，
才认；命中多个就返回 null 退回 toast。宁可不说，也不能指错 ——
指错比不指更糟，用户会盯着一个没问题的框改半天。

关键词因此要写得具体：「课程」单独出现不能当作关键词，
否则「截止时间不能早于课程开始」会被算到「所属课程」头上。

## 常见问题

<details>
<summary><b>我需要买一台服务器吗？</b></summary>

**大多数情况下不需要。** 有一台能长期开着的电脑就够了。

而且如果你主要想要的是「别忘了交作业」，那连远程访问都不用配——
提醒是电脑主动推给 Bark 的，手机不需要能连上你的电脑。

想在外面也能打开网页看课表的话，最省事的是 [Tailscale](#方式三tailscale自用最推荐)（免费、不用公网 IP）。
详见 [部署：让提醒真正可靠](#部署让提醒真正可靠)。
</details>

<details>
<summary><b>电脑关机了，到点的提醒会丢吗？</b></summary>

不会丢，但会晚。

调度器在服务内每 60 秒扫一次。关机期间到点的提醒：

- **7 天以内**：重新启动服务后会补发（虽然已经晚了）
- **超过 7 天**：标记为「过期未发送（服务未运行）」，在页面上能看到

所以想让它真正准时，服务就得一直开着。
</details>

<details>
<summary><b>在手机上打不开，怎么办？</b></summary>

按情况对号入座：

- **在家、连的同一个 Wi-Fi**：`.env` 里 `HOST` 改成 `0.0.0.0` 后重启，
  用终端打印出来的那个局域网地址（`192.168.x.x`）访问，不要用 `127.0.0.1`
- **在外面（4G/5G）**：需要内网穿透，见 [方式三](#方式三tailscale自用最推荐)
- **「添加到主屏幕」后图标或名字不对、也不全屏**：网页应用清单需要 HTTPS 才生效。
  HTTP 下 iOS 仍然能添加，只是效果不完整 —— 见上面 HTTPS 那一节

</details>

<details>
<summary><b>端口被占用怎么办？</b></summary>

编辑 `.env`，改 `PORT=3082`（或任何没被占用的端口），重启。
</details>

<details>
<summary><b>忘记密码了？</b></summary>

用重置脚本，**数据一点不动**：

```bash
node scripts/reset-password.mjs 新密码            # 站点只有一个账号时
node scripts/reset-password.mjs 新密码 用户名      # 有多个账号时必须点名
```

站点里有多个账号却不点名的话，脚本会**直接拒绝并列出所有账号** ——
免得本来想帮同学重置，结果改错了人。

> 老办法「删掉 `data/app.db` 重新初始化」也能让你进去，
> 但**会丢光所有数据**。除非你确实想从零开始，否则别这么做。

</details>

<details>
<summary><b>PPT 预览显示的是「网页版预览」，没有排版？</b></summary>

说明**转 PDF 这一步没成功**，平台退到了内置的文本解析器。

**如果一直是这样**：本机没有可用的转换器。装一个（任一即可）：

- [LibreOffice](https://www.libreoffice.org/)（免费开源，推荐）
- Microsoft Office
- WPS Office

装完重启服务。设置 →「文件预览能力」那一栏会显示当前探测到的是哪个。

**如果以前能正常看、新传的却不行**：老课件的 PDF 早就转好放在缓存里了，
所以只有新传的会暴露问题。跑这个诊断脚本，它会把原因直接打出来：

```bash
node scripts/diagnose-preview.mjs
```

常见原因它都能认出来：转换器没装/调不动、**系统缺中文字体**、磁盘满了、
内存不够、上一次转换超时后留下的僵尸进程把内存占满了。

**如果课件里的中文变成了方框或乱码**（这个问题脚本也会报出来，但你要知道怎么修）：
PDF 是用**服务器上装了的字体**画字的，而云服务器的精简镜像里几乎不带中文字体。
装一下就行，**不用重启服务**：

```bash
sudo apt install -y fonts-noto-cjk fonts-wqy-microhei fonts-wqy-zenhei
```

装完要把已经转好的课件**重转一遍**（旧的 PDF 里画的就是方框，不会自己变好）：

```bash
node scripts/diagnose-preview.mjs --reconvert-all
```

诊断说转换器可用时，也可以直接重试那些没渲染好的：

```bash
node scripts/diagnose-preview.mjs --retry
```

> 另外，预览转换是**排队**跑的（默认同时只跑 1 个）。一次传很多课件时
> 排在后面的会多等一会儿，那是正常的，不是卡住了 ——
> 小内存服务器上同时起好几个 LibreOffice 会被系统杀掉，
> 那才会真的转不出来。机器够大可以设 `PREVIEW_CONCURRENCY=2`。

</details>

<details>
<summary><b>收不到提醒？</b></summary>

按顺序检查：

1. 「设置 → 手机提醒」里渠道是不是**启用**状态，点「测试」看能不能收到
2. 「设置 → 提醒调度」看**调度器是否运行中**（服务必须在跑）
3. 看「发送记录」，失败的话那里有具体错误信息
4. 检查作业的提醒设置：如果 DDL 已经过去，新的提醒就不会再排了
5. iPhone 上如果开了「专注模式」，把 Bark 的通知级别设成**「时效性通知」**，
   并去 iOS「设置 → 通知 → Bark → 时效性通知」把开关也打开
</details>

<details>
<summary><b>邮件渠道报 535 错误？</b></summary>

国内邮箱（QQ / 163）**不能用登录密码**，必须用「授权码」：

- QQ 邮箱：设置 → 账户 → 开启 SMTP 服务 → 生成授权码
- 163 邮箱：设置 → POP3/SMTP/IMAP → 开启服务 → 获取授权码

把授权码填进「授权码」字段，不是登录密码。
</details>

<details>
<summary><b>导入的课表周次不对？</b></summary>

课表周次依赖「学期第 1 周的周一」这个基准日期。
去「设置 → 学期」核对一下，校历上写「第 1 教学周」的那一周的周一就是它。填错了整个课表的周次都会偏。
</details>

<details>
<summary><b>导入的课程时间不对（比如显示 08:00 但实际是 08:30）？</b></summary>

三种情况：

1. **教务系统给的是「第 3-4 节」这种节次写法** —— 平台按「作息时间表」换算，
   而默认那份是通用的、不一定符合你们学校。
   先去「设置 → 作息时间」按你们学校一节一节填好，再重新导入。

2. **教务系统给的就是具体时间，但识别错了** ——
   直接去课程详情页 →「上课时间」→「编辑上课时间」，手动改正即可。

3. **课程表页的时间轴显示的是「08:00、09:00」而不是「第1节、第2节」** ——
   说明本学期的课程时间和你的作息表对不上，平台自动退回了整点分行
   （这样至少能看清，不会把课塞进错误的行）。
   去「设置 → 作息时间」核对一下，或者改单门课的时间。

如果发现是解析逻辑本身的问题，欢迎提 Issue 并附上课表片段。
</details>

<details>
<summary><b>能把整个 data 目录打包发给我同学吗？</b></summary>

技术上可以，但**不建议**：里面有你的推送密钥（Bark Key、邮箱授权码），
拿到的人可以给你发消息。要分享的话，先删掉 `data/app.db` 里的 `notify_channels` 表内容。
</details>

## 参与开发

欢迎 PR。几个容易上手的方向：

### 加一个推送渠道

在 `src/lib/notify/channels.js` 里往 `CHANNELS` 数组加一项就行，
设置页的表单、测试按钮、发送逻辑会自动接上：

```js
{
  type: 'mychannel',
  label: '我的推送',
  tagline: '一句话说明',
  badge: '国内',
  fields: [
    { key: 'token', label: 'Token', type: 'text', required: true },
  ],
  async send(config, msg) {
    // msg: { title, body, url }
    await fetch('https://example.com/push', { /* ... */ });
    return { ok: true, detail: '推送成功' };
  },
}
```

### 加一个教务系统适配器

目前导入走的是通用的 ICS / CSV 路径。想做「输入学号密码自动同步课表」，
可以在 `src/lib/import/` 下新增适配器，参考 `ics-import.js` 的输出格式
（`{ courses: [{ name, teacher, credits, sessions: [...] }] }`），
然后复用 `importCourses()` 写库。
